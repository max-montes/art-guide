# xcodegen-app-spec

## ⚠️ CRITICAL: Regen is mandatory when adding Swift files

**Symptom when you skip it:** Xcode shows a cascade of "Cannot find type X in scope" /
"Cannot find Y in scope" errors for types that clearly exist on disk — because the
`.xcodeproj` compile-phase list hasn't been updated.

**Fix (one command):**
```bash
cd apps/ios && xcodegen generate
```

Then commit the regenerated `.xcodeproj` alongside your new Swift file.

**Automated fix (pre-commit hook, installed 2026-05-16):**
The repo now ships `.githooks/pre-commit` which reruns `xcodegen generate`
automatically when `.swift` files under `apps/ios/` are staged, then stages
the updated `.xcodeproj` into the same commit. Install once per clone:
```bash
./setup-hooks.sh   # from repo root
# or: git config core.hooksPath .githooks
```

## Problem

Hand-rolling an Xcode project for a SwiftUI iOS app is tedious and easy to
get subtly wrong. The two settings people get wrong most often:

1. **`GENERATE_INFOPLIST_FILE` defaults to `YES`** in modern Xcode and
   silently shadows any `Info.plist` you have on disk. The result: your
   camera/photo permission strings, custom URL keys, etc., never make it
   into the built app and you spend an afternoon wondering why
   permissions aren't being prompted.
2. **`xcconfig` files have to be wired per configuration** (Debug AND
   Release) at the right level (project or target). Easy to set on one
   and forget the other.

[XcodeGen](https://github.com/yonaskolb/XcodeGen) generates the
`.xcodeproj` from a YAML spec, encoding both settings explicitly so they
can't drift.

## Reusable spec shape

```yaml
name: <AppName>

options:
  bundleIdPrefix: <reverse.dns.prefix>
  deploymentTarget:
    iOS: "16.0"
  createIntermediateGroups: true
  groupSortPosition: top

settings:
  base:
    SWIFT_VERSION: "5.9"
    IPHONEOS_DEPLOYMENT_TARGET: "16.0"
    DEVELOPMENT_TEAM: ""           # auto-fills on first Xcode open
    CODE_SIGN_STYLE: Automatic

targets:
  <AppName>:
    type: application
    platform: iOS
    deploymentTarget: "16.0"

    sources:
      - path: <AppName>
        excludes:
          - "Info.plist"                       # wired below; not a source
          - "Config/Config.xcconfig"           # wired below; not a source
          - "Config/Config.local.xcconfig"     # local override, gitignored
          - "**/.DS_Store"

    configFiles:
      Debug:   <AppName>/Config/Config.xcconfig
      Release: <AppName>/Config/Config.xcconfig

    settings:
      base:
        PRODUCT_BUNDLE_IDENTIFIER: <reverse.dns.prefix>.<appname>
        PRODUCT_NAME: <AppName>
        # The two settings that make the on-disk Info.plist actually win.
        GENERATE_INFOPLIST_FILE: NO
        INFOPLIST_FILE: <AppName>/Info.plist
        MARKETING_VERSION: "0.1.0"
        CURRENT_PROJECT_VERSION: "1"
        TARGETED_DEVICE_FAMILY: "1,2"
        ENABLE_PREVIEWS: YES
        CODE_SIGN_STYLE: Automatic
        DEVELOPMENT_TEAM: ""

schemes:
  <AppName>:
    build:
      targets:
        <AppName>: all
    run:
      config: Debug
      # Pre-declare any env vars testers will want to flip without
      # recompiling. Even with isEnabled: true, they show up in
      # Edit Scheme → Run → Environment Variables for easy editing.
      environmentVariables:
        - variable: <YOUR_RUNTIME_FLAG>
          value: <default>
          isEnabled: true
    test: { config: Debug }
    profile: { config: Release }
    analyze: { config: Debug }
    archive: { config: Release }
```

## Companion `setup.sh`

```bash
#!/usr/bin/env bash
set -euo pipefail
cd "$(dirname "$0")"

if ! command -v xcodegen >/dev/null 2>&1; then
  echo "xcodegen not found. Install with: brew install xcodegen" >&2
  exit 1
fi

xcodegen generate
echo "✅ <AppName>.xcodeproj generated. Open with: open <AppName>.xcodeproj"
```

`chmod +x setup.sh`. Document `brew install xcodegen` in the README.

## Sanity checks after generating

```bash
xcodebuild -project <AppName>.xcodeproj -list
xcodebuild -project <AppName>.xcodeproj -scheme <AppName> \
  -destination 'generic/platform=iOS Simulator' \
  -configuration Debug build CODE_SIGNING_ALLOWED=NO
```

The first should list the scheme + target. The second compiles without
needing a signing identity — useful in CI or on a fresh clone.

## Known gotchas

- **xcconfig comment syntax bites URLs.** `//` starts a comment even
  inside a value. Escape with `$()`: `API_BASE_URL = https:/$()/example.com`.
- **Adding Swift files requires regen.** The spec uses a directory glob,
  not a file list. The `.xcodeproj` is static between `xcodegen generate`
  runs. Every time you add a new `.swift` file (or folder) to disk, you
  must re-run `xcodegen generate` and commit the updated `.xcodeproj` or
  Xcode will show "Cannot find X in scope" for all types in the new file.
  This failure pattern has occurred twice in this project (2026-05-10,
  2026-05-16).
- **Unit-test target needs `GENERATE_INFOPLIST_FILE: YES`.** Unlike the
  app target (which pins an on-disk plist), the test bundle has no custom
  `Info.plist`. Add this to the test target's `settings.base` or code
  signing will fail: `GENERATE_INFOPLIST_FILE: YES`.
- Don't put the `Info.plist` or xcconfig under `sources:` without the
  `excludes:` block above; XcodeGen will otherwise add them as resources
  and you'll see duplicate-Info.plist warnings.
